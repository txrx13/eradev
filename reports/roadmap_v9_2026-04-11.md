### Phase 1 — Vocabulary Refactor + Adapter Layer (2-3 days)

**1.A Role file vocabulary refactor ([BUILDER] EN+RU parallel):**
- Rewrite all 10 role files (5 EN + 5 RU)
- Replace code-specific vocabulary with abstract:
  - `code` → `artifact`
  - `compile` → `verify`
  - `test` → `validate`
  - `build` → `produce`
  - `git` → `version control / tracked changes`
- Add 3 inline examples per role (code, article, book) — domain-agnostic illustration
- Preserve all formal structures (Activation Operator, Jidoka, Output Format)
- BL-19 mandatory: EN and RU updates in same commit

**1.B Domain adapter schema ([ANALYST] + [BUILDER]):**
- Add `domain:` block to all 4 existing project configs (eradev, plugy, odtoe-articles, academic-lab)
- Schema:
  ```yaml
  domain:
    type: code | article | book | config | plan
    artifact: source_file | section | chapter | yaml | document
    verify: build_command | citation_check | readability | parse | dry_run
    examples:
      - "source -> compile -> test -> deploy"  # code
      - "outline -> draft -> review -> publish"  # article
  ```
- Existing projects work unchanged (default `type: code` for backward compat)

**1.C Universal CLAUDE.md ([BUILDER]):**
- Update CLAUDE.md template with domain-aware Session Bootstrap
- Add Session Bootstrap item: `[ ] DOMAIN: type ___ verify_method ___`
- Update KILL-TEST: detect domain from project config

**1.D BL split ([COHERENCER]):**
- Split BOOTSTRAP_LESSONS.md into 2 parts:
  - `BOOTSTRAP_LESSONS_universal.md` (~22 BL — universal)
  - `BOOTSTRAP_LESSONS_code_adapter.md` (~8 BL — code-specific)
- Both auto-loaded by code projects, only universal by non-code
- Maintain BL numbering across both files

**1.E Phantom Coherence Check L2 ([VALIDATOR]):**
- After Phase 1 implementation, run cross-source independence check
- Spawn fresh agent with no prior context, ask "is this universalization coherent?"
- Compare to L2 team syntheses — if S_team drops by >0.15, phantom coherence detected → rollback
