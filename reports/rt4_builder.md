## I. АУДИТ: Что из ODTOE уже реализовано в eradev_last

### 1.1. Реализовано и работает

Текущая версия eradev.md уже содержит значительный пласт ODTOE. Перечислю конкретно.

**Формула когерентности B = F^w1 * E^w2 * (1-sigma)^w3 * Lambda^w4** -- присутствует в секции "Теоретический фундамент: ODTOE когерентность" (строки 488-503). Для каждой компоненты дана интерпретация применительно к AI-агентам: F = прочитал ли нужные файлы, E = соответствует ли результат задаче, (1-sigma) = нет ли конфликтов в коде, Lambda = использован ли MEMORY.md. Принцип мультипликативности ("если ЛЮБОЙ компонент = 0, вся когерентность = 0") подчёркнут как критически важный.

**Коллективная когерентность P5.1** -- формула P_coll(E) = 1 - PROD(1 - Bi^k) присутствует (строки 505-514) с числовыми примерами (3 агента -> 0.61, 5 -> 0.83, 10 -> 0.97).

**Когерентность команды S** -- формула S_team = 1 - (2/n(n-1)) * SUM|Bi - Bj| присутствует (строки 518-523) с привязкой к времени жизни конфигурации T(C) = T0 / (1-S)^n.

**Уровни 3-6-9** -- присутствуют (строки 525-680) с конкретной привязкой: Level 3 = Builder проверяет компиляцию, Level 6 = полный цикл RT с обратной связью, Level 9 = Meta-Agent модифицирует промпты агентов. Описана архитектура Meta-Agent (строки 575-594), эволюция промптов, спиральная память, Prediction Delta цикл.

**Спиральный зазор ~2%** -- упомянут (строки 533-535): "(pi-3)^2 ~ 0.02 -- не баг, а двигатель развития".

**Тороидальная топология** -- описана (строки 537-547): внутреннее кольцо r (Аналитик-Строитель-Валидатор) и внешнее R (Визионер-Когерент-Аналитик), отношение R/r = phi.

**Пятёрка как минимальная устойчивая группа** -- реализована как базовая архитектура: Визионер + Аналитик + Строитель + Валидатор + Когерент. Соответствует ODTOE_coherent_education формуле n_min = 3 (скелет петли) + 2 (избыточность) = 5.

### 1.2. НЕ реализовано или реализовано поверхностно

**Четырёхтактный когнитивный цикл (расширение-сжатие-расширение-сжатие)** -- отсутствует. ODTOE_coherent_education описывает четыре такта: (1) формулировка проблемы = расширение, (2) определение ключевого понятия = сжатие, (3) поиск аналогов = расширение, (4) решение и фиксация = сжатие. Пропорция phi/(1+phi) для расширения и 1/(1+phi) для сжатия. В текущем EraDev Round Table не структурирован по этим тактам.

**Динамика когерентности dB/dt** -- уравнение dB/dt = gamma * tanh(beta * d_dot) * d_bar * B(1-B) не используется. Два поглощающих состояния (B=0 -- утрата мотивации, B=1 -- закрытость) не отслеживаются. Агенты не мониторят, не находятся ли они в зоне аттрактора.

**B-профиль с диагностикой дефицитов** -- в eradev есть упоминание компонент B, но нет механизма диагностики: какой именно дефицит (F, E, sigma, Lambda) доминирует у конкретного агента в конкретной сессии и какая стратегия коррекции применяется.

**Оператор активации A_hat = A_Lambda o A_sigma o A_E o A_F** -- не реализован. ODTOE_AI_369_AGI (строки 156-171) описывает последовательный четырёхшаговый оператор: сначала фокусировка, затем согласование, затем разрешение противоречий, затем накопление опыта. Это прямая инструкция для каждого агента перед генерацией ответа.

**Золотое сечение в пропорциях циклов** -- упомянуто в тороидальной топологии (R/r = phi), но НЕ применено к временным пропорциям: длительности RT-1 vs реализации vs RT-2 vs доработки vs RT-3 не привязаны к phi.

**SKW-матрица** (Ситуация-Ключевое слово-Вопросы: зачем, как, кто, когда, ресурсы) -- не используется как формат вывода агентов, хотя ODTOE_coherent_education предлагает её как "элементарную единицу когерентного образования".

**Формула скорости переконфигурации v = alpha / (I(C) + epsilon)** -- не применяется для оценки инерции задачи. Понятие инерции конфигурации I(C) могло бы помочь при классификации задач (S/M/L/XL).

**Когерентное расширение контекста** -- ODTOE_AI_369_AGI (строки 278-322) предлагает мультипликативный ранг для RAG: B_retrieval = F_query^w1 * (1-sigma_contradiction)^w3 * Lambda_freshness^w4. Это не реализовано -- агенты загружают файлы без оценки когерентности контекста.

**Функция Ляпунова для устойчивости самомодификации** -- ODTOE_AI_AGI_EXPANSION описывает V(O_hat) = ||O_hat - O_hat*||^2 + alpha * (1 - B(O_hat))^2 и условие Delta_V < 0 для каждой итерации. В EraDev Meta-Agent не использует критерий Ляпунова при модификации промптов.

**Фантомная когерентность S_phantom vs S_true** -- ODTOE предупреждает о риске, когда видимая когерентность выше реальной. В EraDev нет механизма проверки: агенты могут формально "согласиться" (высокий S_phantom) при реальном рассогласовании (низкий S_true).

## II. КОНКРЕТНЫЕ ФРАГМЕНТЫ ПРОМПТОВ ДЛЯ ВСТРАИВАНИЯ

### 2.1. Оператор активации -- вставить в КАЖДЫЙ промпт агента

Это самое важное добавление. Каждый агент перед генерацией ответа должен пройти четыре шага в определённом порядке. Вот фрагмент для встраивания в начало каждого role-файла (visionary.md, analyst.md, builder.md, validator.md, coherent.md):

```
=== ОПЕРАТОР АКТИВАЦИИ (выполняй ДО генерации ответа) ===
Шаг 1 (A_F -- Фокус): Определи релевантные файлы и контекст.
  Загрузи ТОЛЬКО то, что нужно. Отсеки нерелевантное.
  Если не уверен что именно читать -- СТОП, спроси.

Шаг 2 (A_E -- Согласование): Перечитай задачу.
  Убедись что твой ответ будет соответствовать НАМЕРЕНИЮ, а не букве.
  Сверься с Pull-якорем: ИКР всё ещё актуален?

Шаг 3 (A_sigma -- Непротиворечивость): Проверь на конфликты.
  Нет ли противоречий с существующим кодом, архитектурой, MEMORY.md?
  Если есть -- разреши ДО генерации ответа.

Шаг 4 (A_Lambda -- Опыт): Обратись к памяти.
  Прочитай memories/{project}.md. Был ли аналогичный случай?
  Какие паттерны применимы?

Только после 4 шагов -- генерируй результат.
```

### 2.2. B-диагностика в Jidoka Self-Check -- расширить существующий шаблон

Текущий Jidoka Self-Check проверяет шаблонность (X/10). Нужно добавить B-диагностику:

```
=== JIDOKA SELF-CHECK (расширенный) ===
1. Оценка шаблонности: X/10
2. B-диагностика (оцени 0.0-1.0 для своего ответа):
   F (Фокус):       ___ / 1.0  -- Все ли нужные файлы прочитаны?
   E (Alignment):   ___ / 1.0  -- Ответ решает ИМЕННО эту задачу?
   (1-sigma):       ___ / 1.0  -- Нет противоречий с существующим?
   Lambda (Опыт):   ___ / 1.0  -- MEMORY.md учтён?
   B (итого):       ___ (произведение четвёртых корней)
3. Если B < 0.5: Какая компонента слабая? Что исправить?
4. Если min(F,E,1-sigma,Lambda) < 0.3: АНДОН -- слабое звено обнулит всё.
```

### 2.3. Четырёхтактный цикл для Round Table -- новая структура RT

Текущий RT имеет три точки (RT-1, RT-2, RT-3). Предлагаю внутри каждого RT структурировать работу по четырём тактам:

```
=== ЧЕТЫРЁХТАКТНЫЙ ЦИКЛ ROUND TABLE ===

Такт 1 (Расширение, ~phi/(1+phi) = 62% времени такта):
  Визионер + Аналитик сканируют пространство задачи.
  Формат вывода: SKW-матрица (Зачем? Как? Кто? Когда? Ресурсы?)

Такт 2 (Сжатие, ~1/(1+phi) = 38% времени такта):
  Строитель + Валидатор фокусируют: ключевое решение, главный риск.
  Формат: одно предложение -- ЯДРО задачи.

Такт 3 (Расширение):
  Все 5: поиск аналогов в memories/, прецедентов, смежных решений.

Такт 4 (Сжатие):
  Когерент: фиксация решения, запись в A3.
  Формат: SKW-матрица заполнена, противоречия разрешены.
```

### 2.4. Детектор фантомной когерентности -- новый протокол для RT-2

```
=== PHANTOM COHERENCE CHECK (Когерент запускает в RT-2) ===
Вопрос каждому агенту ОТДЕЛЬНО (не видя ответов других):
  "Опиши в одном предложении: что мы делаем и зачем?"

Сравнить 5 ответов:
  Если 4+ ответа совпадают по смыслу -> S_true >= 0.8, ОК.
  Если 2-3 расхождения -> S_true ~ 0.5, нужна синхронизация.
  Если каждый описывает другое -> S_true < 0.3, АНДОН.

Это тест на РЕАЛЬНУЮ когерентность, не на формальное согласие.
```

### 2.5. Инерция конфигурации для классификации задач -- расширить таблицу S/M/L/XL

```
=== КЛАССИФИКАЦИЯ ЧЕРЕЗ ИНЕРЦИЮ I(C) ===

I(C) = кол-во_файлов * средняя_связность * legacy_фактор

| Размер | I(C)    | v = alpha/(I(C)+eps) | Минимум RT |
|--------|---------|----------------------|------------|
| S      | < 5     | Высокая              | 0 (прямое) |
| M      | 5-20    | Средняя              | 1 RT       |
| L      | 20-50   | Низкая               | 3 RT       |
| XL     | > 50    | Очень низкая         | 3 RT + L2  |

Чем выше инерция -- тем больше RT-циклов нужно для переконфигурации.
```

## III. МИНИМАЛЬНЫЙ НАБОР ТЕОРИИ ДЛЯ КАЖДОЙ РОЛИ

Принцип: каждый агент получает ТОЛЬКО ту теорию ODTOE, которая непосредственно влияет на качество его работы. Избыточная теория -- это Muri (перегрузка).

### 3.1. Визионер (visionary.md)

Минимум теории:
- Формула B = F * E * (1-sigma) * Lambda (мультипликативность -- любой ноль убивает всё)
- Уровни мерности d: d=1 запоминание, d=2 понимание, d=3 рефлексия, d=4 создание
- Спиральный зазор ~2%: идеальное решение невозможно, и это нормально -- 2% питают следующий виток
- Такт 1 и Такт 3 когнитивного цикла -- фазы расширения, где Визионер доминирует

Чего НЕ давать: формулы P5.1, S_team, динамику dB/dt, кватернионную модель.

### 3.2. Аналитик (analyst.md)

Минимум теории:
- Формула B -- все 4 компоненты, с фокусом на (1-sigma): Аналитик -- главный ответственный за непротиворечивость плана
- Инерция конфигурации I(C): чем больше связей между компонентами, тем дороже изменение
- v = alpha / (I(C) + epsilon): скорость переконфигурации обратно пропорциональна инерции
- File Ownership как следствие: пересечение файлов между Строителями повышает I(C) и sigma

Чего НЕ давать: уровни 3-6-9, тороидальную топологию, золотое сечение.

### 3.3. Строитель (builder.md)

Минимум теории:
- Оператор активации A = A_Lambda o A_sigma o A_E o A_F -- четыре шага перед написанием кода
- Принцип слабого звена: если F=0 (не прочитал нужный файл), вся работа = 0
- Level 3 = самопроверка: компиляция, тесты, lint ПЕРЕД отдачей результата
- Lambda: всегда проверяй memories/ -- повторение ошибки = Lambda -> 0

Чего НЕ давать: коллективные формулы, динамику, мета-уровень.

### 3.4. Валидатор (validator.md)

Минимум теории:
- B-диагностика: при нахождении бага -- классифицировать по дефициту (F/E/sigma/Lambda)
- P_coll: даже слабый Валидатор в команде с другими агентами повышает общую вероятность -- не молчи, любое замечание ценно
- Фантомная когерентность: S_phantom vs S_true -- проверяй не формальное "все согласны", а реальное понимание
- Level 3 самопроверка: применяй к собственному чеклисту (не пропустил ли я пункт?)

Чего НЕ давать: SKW-матрицу, тороидальную топологию, динамику обучения.

### 3.5. Когерент (coherent.md)

Минимум теории (максимальный набор из всех ролей -- Когерент = "процессор когерентности"):
- Формула B со всеми компонентами + механизм слабого звена
- S_team = 1 - (2/n(n-1)) * SUM|Bi - Bj| -- Когерент должен уметь оценивать S
- T(C) = T0 / (1-S)^n -- чем выше S, тем устойчивее результат
- Четырёхтактный цикл -- Когерент контролирует чередование расширения и сжатия
- Фантомная когерентность -- Когерент единственный кто обязан её детектить
- Кристаллизация = повышение Lambda для будущих сессий
- Спиральный зазор -- Когерент фиксирует ~2% нерешённого как "топливо" следующего витка

Чего НЕ давать: формулы AGI, функцию Ляпунова, NAS, кибернетику Кибальникова.

### 3.6. Meta-Agent (meta.md)

Минимум теории (полный набор, это единственная роль с доступом ко всей теории):
- Всё что у Когерента + уровни 3-6-9 + оператор самомодификации M_hat
- Функция Ляпунова: Delta_V < 0 для каждой модификации промптов
- Условие: модификация промпта, повышающая одну компоненту B, но обнуляющая другую -- запрещена
- Prediction Delta Tracking как эмпирическая реализация dB/dt

## V. ПОРЯДОК ВНЕДРЕНИЯ (рекомендация Строителя)

1. **Немедленно** (0 рисков, чистый прирост): Вставить Оператор активации в role-файлы. Это 4 конкретных шага, которые любой агент может выполнить сразу.

2. **Следующий цикл**: Расширить Jidoka Self-Check до B-диагностики. Это даёт мгновенную обратную связь по качеству.

3. **Через 1-2 цикла**: Ввести четырёхтактный цикл в RT. Требует тестирования -- не факт что агенты сразу выдержат структуру.

4. **После стабилизации**: Фантомная когерентность, инерция задач, ODTOE-метрики в memories/.

5. **Не раньше Level 7**: Функция Ляпунова в Meta-Agent. Требует накопления данных (минимум 10 циклов Prediction Delta).

## VI. ГЛАВНЫЙ ВЫВОД СТРОИТЕЛЯ

Текущий eradev.md -- уже сильная реализация ODTOE Level 6. Формула B присутствует, пятёрка работает, Round Table замкнут в петлю, спиральная память и Meta-Agent описаны. Основной разрыв -- между ОПИСАНИЕМ теории и её ОПЕРАЦИОНАЛЬНЫМ встраиванием в промпты агентов. Формулы есть в тексте eradev.md, но агенты их не используют в момент генерации ответа, потому что формулы находятся в "теоретической" секции, а не в "инструкционной" части промптов.

Ключевое действие: превратить теорию из "справочного раздела" в "рабочий чеклист". Оператор активации (раздел 2.1) -- это тот самый мост. Четыре шага A_F -> A_E -> A_sigma -> A_Lambda, встроенные в начало каждого промпта, заставят каждого агента ПРИМЕНЯТЬ ODTOE, а не просто "знать" о ней. Это разница между уровнем 3 (знание) и уровнем 6 (применение с обратной связью).

Второй по важности шаг -- B-диагностика в Jidoka Self-Check. Без неё агент не знает, какой именно компонент когерентности у него проседает, и не может целенаправленно это исправить.

Всё остальное -- оптимизация. Эти два шага -- фундамент.
