## 2. Конкретные изменения в каждом файле

### 2.1 eradev.md (1062 -> 1255, +18.2%)

Это центральный манифест фреймворка. Между версиями произошла существенная структурная перестройка. В old-версии файл начинался с раздела "Обзор", сразу переходя к True North и Андон. В last-версии документ открывается блоком "ПЕРВОЕ ДЕЙСТВИЕ НОВОЙ СЕССИИ" -- инструкцией прочитать MEMORY.md, затем память проекта, затем ROADMAP. Это организационное изменение переводит файл из описательного формата в операционный: вместо того чтобы объяснять что такое EraDev, он сразу говорит агенту что делать.

Добавлено два выделенных железных правила с красными маркерами: "Мета-Оркестратор НИКОГДА не делает задачи сам" и "Минимум 5 агентов на КАЖДУЮ задачу". В old-версии эти правила упоминались, но не имели такого акцента. В last-версии они вынесены в начало файла и снабжены подробными объяснениями (зачем параллелизация, зачем специализация, формула ODTOE). Добавлена полная схема масштабирования команд (ASCII-диаграмма МЕТА-ОРКЕСТРАТОР -> Команда A/B/C -> Когерент-L2 -> Когерент-L3), формула расчета числа команд (N_teams = ceil(N_modules / 3)), и таблица классификации задач S/M/L/XL с минимальным числом агентов для каждого размера.

Добавлены File Ownership Protocol (разметка кто какие файлы правит при параллельной работе), стандартизированный формат выхода агентов (максимум 500 слов), и Timeout/Circuit Breaker для агентов (5 минут таймаут, 3 минуты дополнительно при видимом прогрессе, затем замена). Появилась полная иерархия когерентов L1/L2/L3 с ASCII-диаграммой трёхуровневой структуры.

Весь блок от True North до конца (TPS, A3, Bottleneck Expansion Protocol, Session Architecture, Jidoka, Kill-Switch, Mura/Muri, Prediction Delta, ODTOE, Round Table) перенесён практически без изменений, но смещён вниз -- после блока про Мета-Оркестратора. Это приоритизация операционной информации над теоретической.

### 2.2 builder.md (222 -> 240, +8.1%)

Базовая структура файла (роль, обязанности, правила кода Go/TypeScript/Bash, Security Checklist, Jidoka Self-Check, антипаттерны, уроки Витков 1-4) идентична в обеих версиях -- ни одна строка не была удалена. Все 19 паттернов от Meta-Agent (P1-P19) и Decision-Point Checklist сохранены полностью.

Добавлен новый блок "Уроки от Когерент-L3 (Виток 6: 2026-04-01)" с четырьмя паттернами. P20 вводит STOP-правило для scroll/touch -- обязательный тест в 3 браузерах перед написанием кода (Chrome, Safari, Яндекс Браузер). P21 запрещает Big Bang PWA: максимум 2 PWA/mobile фазы за сессию, обязательное тестирование на реальном устройстве после каждой. P22 фиксирует конкретный CSS-баг: overflow-x:hidden только на body, никогда на html (ломает position:sticky). P23 запрещает дублирование scroll/overflow управления если фреймворк (Radix/Next.js/Shadcn) уже этим управляет.

Источник этих паттернов примечателен: это не Meta-Agent (как P1-P19), а Когерент-L3. Это показывает что система обратной связи расширилась: теперь не только Meta-Agent вносит правила, но и другие роли имеют механизм фиксации уроков.

### 2.3 meta.md (814 -> 1116, +37.1%)

Наибольший абсолютный рост среди существующих файлов. Весь контент old-версии (роль, метрики, археология коммитов, инструменты, спиральная память витков 1-3) сохранён полностью.

Добавлен целый Виток 4 (2026-04-01). Сессия описана количественно: 77 коммитов, 119 файлов, 18519 строк, 40 fix-коммитов (52%), 8 HOTFIX, 2 revert. Виток содержит 6 подробно разобранных инцидентов: M1 (IPv6 saga -- 7 коммитов, полный откат, B=0), M2 (refuse_when_unhealthy -- DNS outage, B=0), M3 (HTTP/2 double TLS wrap -- crash 7/8 нод, B=0.02), M4 (cascade proxy -- 3 fix-а, B=0.01), M5 (config backwards compatibility crash), M6 (pnpm build not run before push). Для каждого инцидента вычислена формула когерентности B = F x E x (1-sigma) x Lambda.

Добавлен тренд-анализ fix rate по всем 5 сессиям (67% -> 57% -> 64% -> 40% -> 52%), из которого видно что эффект EraDev ослаб в пятой сессии. Проведён анализ "почему правила Витков 1-3 не сработали" -- выявлены четыре gap-а: абстрактное правило без процедуры, отсутствие разделения creation/activation для feature flag, single-hop vs multi-hop правило, правило без enforcement. Добавлены мега-паттерны MP5-MP8 и adversarial review (MM3) с 4 сценариями обхода. Ключевое открытие Витка 4: Lambda=0 проблема -- правила существуют, но игнорируются, нужен enforcement.

### 2.4 validator.md (302 -> 323, +7.0%)

Аналогично builder.md: вся базовая структура и все 16 паттернов (P1-P16) сохранены. Добавлен блок "Уроки от Когерент-L3 (Виток 6)" с тремя паттернами. P17 вводит fix chain detector: 3+ fix коммитов на одну тему = блокировка следующего fix до прохождения specification step (описать поведение, root cause, тест). Счётчик ведётся по тегам (scroll, layout, safe-area, touch, overflow). P18 вводит правило "Revert = красная карта": после revert обязателен postmortem до продолжения работы, postmortem записывается в MEMORY.md. P19 вводит cross-browser gate для scroll/touch: обязательная проверка в 3 браузерах с evidence (скриншоты или текстовый отчёт), без evidence -- no-go.

### 2.5 coherent.md (156 -> 199, +27.6%)

Второй по относительному росту файл. В old-версии Когерент описан как единая роль. В last-версии добавлена полная иерархия L1/L2/L3 с описанием каждого уровня: L1 (внутри команды, запускается ВСЕГДА), L2 (между командами, при 2+ параллельных), L3 (глобальный, при 5+ командах). Добавлены триггеры эскалации: L1->L2 при обнаружении файлов затронутых другой командой, L2->L3 при архитектурном конфликте. Добавлен протокол конфликтов для L2: приоритет по blast radius, при равном -- merge последовательно. Добавлены шаблоны запуска для Мета-Оркестратора (Agent("Ты -- Когерент-L1/L2/L3...")).

В Decision Log добавлены 3 новых записи от 2026-04-01: "Мета-Оркестратор = диспетчер" (CRITICAL), "Минимум 5 агентов для M+" (HIGH), "Когерент L1/L2/L3 иерархия" (HIGH). Это отражает фиксацию организационных решений как архитектурных.

### 2.6 visionary.md и analyst.md (без изменений)

Оба файла идентичны между версиями. Visionary.md содержит 67 строк, analyst.md -- 89 строк. Это может указывать на то, что эти роли стабилизировались раньше и не требовали доработки в последних витках, либо на то, что паттерны для них ещё не были извлечены из Витков 4-6.

## 3. Новые файлы в last-версии

### 3.1 MEMORY.md (172 строки)

Полностью новый файл, отсутствующий в old-версии. Выполняет функцию операционной инструкции для Мета-Оркестратора -- определяет КАК работает новая сессия. Содержит: определение роли (МЕТА-ОРКЕСТРАТОР = НИКОГДА не делает задачи сам), таблицу минимума агентов по размеру задачи (S=2, M=5, L=5-8, XL=10+), процедуру быстрого старта сессии (5 шагов), полные шаблоны запуска RT-1 (5 параллельных агентов), шаблоны запуска Строителей по модулям, шаблоны запуска Валидатора + Когерента.

Содержит иерархию когерентов (L1/L2/L3), File Ownership Protocol с конкретной разметкой (Builder-Go, Builder-TS, Builder-Docs), 8 железных правил (включая enforcement hooks для pre-push git hook и правило max 2 PWA/mobile фаз за сессию), формулу ODTOE когерентности (B = F x E x (1-sigma) x Lambda), и реестр ссылок на все файлы фреймворка.

Появление MEMORY.md -- ключевое структурное изменение. В old-версии вся информация была распределена по eradev.md и coherent.md. В last-версии появилась выделенная точка входа, которая сокращает время загрузки контекста для новой сессии.

### 3.2 projects/academic-lab.md (50+ строк)

Новый файл в новой директории projects/. Содержит конкретику проекта Academic Lab: архитектуру (eradns, eraweb, eradeploy, Erachain, Next.js, autodeploy, EraDev), реестр 7 нод (Торонто, Германия, Сан-Пауло, Нью-Йорк, Турция, Новосибирск, Тель-Авив), инструкцию развёртывания новой ноды (7 шагов от SSH до autodeploy), ссылку на Web3 Architecture Plan, и первые 2 железных правила.

Появление директории projects/ сигнализирует о переходе от монопроектного фреймворка к мультипроектному: EraDev отделяет свои метаправила (eradev/*.md) от конкретики проекта (projects/*.md). В old-версии проектная информация хранилась в общем MEMORY.md или docs/.

## 5. Качественные выводы

### 5.1 Эволюция от описательного к операционному

Главный структурный сдвиг между версиями -- переход от описательного формата (что такое EraDev, теория ODTOE) к операционному (что делать при старте сессии, как запускать агентов). Появление MEMORY.md как точки входа, вынос железных правил в начало eradev.md, добавление конкретных шаблонов запуска -- всё это снижает время от "открыл файл" до "начал продуктивную работу".

### 5.2 Эволюция от монолитного к иерархическому

В old-версии Когерент -- единая роль. В last-версии -- иерархия L1/L2/L3 с явными триггерами эскалации и протоколами конфликтов. Появился явный протокол масштабирования команд (формула N_teams, ASCII-диаграммы). Это подготовка к работе с большими задачами, требующими 10+ агентов.

### 5.3 Расширение источников обучения

В old-версии все уроки приходили от Meta-Agent (Витки 1-3). В last-версии появился новый источник: Когерент-L3 (Виток 6), который добавил паттерны в builder.md и validator.md. Это показывает что рефлексивная петля расширилась: не только один Meta-Agent улучшает систему, но и другие роли вносят формализованные уроки.

### 5.4 Обнаружение Lambda-проблемы

Ключевое открытие Витка 4 (присутствующего только в last-версии): правила накапливаются (37 в builder.md, 11 в validator.md), но агенты их не применяют. Lambda (опыт) = 0 несмотря на наличие знаний. Предложенное решение: enforcement > documentation (pre-push hooks, checklists at decision points, prompt compression).

### 5.5 Отделение фреймворка от проекта

Появление директории projects/ с файлом academic-lab.md показывает движение к мультипроектной архитектуре: EraDev как универсальный фреймворк vs конкретные проекты как его инстансы. В old-версии проект и фреймворк были переплетены.

## 6. Риски и рекомендации

1. **Рост объёма промптов**: meta.md вырос на 37.1% до 1116 строк. Сам Виток 4 диагностирует эту проблему: "534 строки meta.md + 154 строки builder.md = перегрузка. Агент не может удержать 700 строк правил в контексте." Рекомендация: иерархическая компрессия (5 железных правил всегда + domain-specific по запросу).

2. **Неравномерность обновлений**: visionary.md и analyst.md не менялись, тогда как meta.md вырос на 37%. Это может создать дисбаланс: Meta-Agent перегружен правилами, а Визионер и Аналитик остаются с базовым набором. Рекомендация: проверить покрытие уроков Витков 4-6 для всех ролей.

3. **Lambda-проблема не решена**: last-версия диагностирует проблему (правила игнорируются) и предлагает enforcement, но сами enforcement hooks ещё не реализованы. Железное правило 7 в MEMORY.md говорит об этом, но пока это документация, а не код. Рекомендация: реализация pre-push git hook как первый шаг enforcement.
