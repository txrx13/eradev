## 3. What went well

### 3.1 Scope discipline at Phase 0.A
The Visionary/Analyst pair explicitly bounded the v9 charter to **text-discrete artifacts only**. Continuous/flow tasks (streaming, real-time simulation, live data pipelines) were named and REJECTed into v10+. This was the single most load-bearing decision of the entire cycle: without the cut, the domain schema would have swallowed latency budgets, backpressure semantics, and real-time constraints — none of which fit the B-formula's multiplicative gate structure.

**The Visionary phase must name what is OUT of scope, not just what is IN.**

### 3.2 Modal B-formula preserved invariant structure
B = F·E·(1-σ)·Λ generalized from code to text/article/book without changing shape. Only the relative weights shift across modalities (text / creative / research). The product form survived because multiplicative AND-gating of 4 orthogonal failure modes is a domain-invariant concept, not a code-specific one.

**When an abstraction generalizes without changing shape, that's evidence it was already the right abstraction — it was being applied in a narrower domain than necessary.**

### 3.3 4-layer architecture is backward-compat by construction
L0 IMMUTABLE framework / L1 universal role archetypes / L2 domain skins / L3 project instances. Any v8 code project loads identically under v9 because absent `domain:` block → defaults to type=code, B_modality=text, ood_scope=text-discrete, verify.method=build. Phase 1.E AC-3 verified this with a zero-diff walkthrough — not proof-by-assertion.

### 3.4 BL tagging produced structural clarity
22 [UNIVERSAL] + 8 [CODE-ADAPTER] = 30 BL. The split file pair makes it mechanically obvious which BL a future domain skin inherits vs overrides. No more "which lessons apply to my article project?" judgment calls.

### 3.5 Self-loading context architecture scaled to 20+ parallel agents
v8 introduced agent self-loading (each agent Reads roles/{role}_EN.md as its FIRST action instead of META embedding the role file content). v9 stress-tested it: 20+ parallel agents across 5 waves, each loading the **current** role file — so Phase 1.A vocabulary refactors automatically propagated to Phase 1.B/1.C/1.D/1.E agents without META having to re-embed anything. Zero context pollution at META level. Zero version drift across agents.

### 3.6 Phantom Coherence Check caught real drift
Phase 1.E surfaced 3 defects (skill mirror v8-era, Russian 5b DOMAIN missing, template phrasing inconsistent) that RT-1 consensus had missed. None would have failed a naive smoke test. All three would have poisoned the next cold-start operator. S_adjusted = S_team × B_mean is dissonance-amplifying by construction: high S without high B is precisely where phantom lives.

### 3.7 Wave-based parallelization compressed v9 into one session
Invariant 13 ("maximize parallelization") was applied at **project scale**, not just RT scale. Waves 1-5 spawned 20+ agents; sequential dependency was only *between* waves (Wave N synthesis → Wave N+1 plan), not *within* waves. What would have been multi-session serial execution became single-session parallel execution.

## 4. What went wrong (and what we fixed)

### 4.1 Hook Check 5 was English-only
`agent-context-check.sh` Check 5 originally matched the English "read" verb. When 5 RU Round Table agents were spawned in parallel, they were all blocked — the Russian "Прочитай" didn't match the regex.

**Fix:** Made the regex language-agnostic, path-only matching (`roles/(visionary|analyst|builder|validator|coherent)(_EN)?\.md`). The enforcement surface is now the file path itself, not the lexical signal around it.

**Lesson learned:** When invariants are enforced by regex, any language-bound lexical signal is a bug waiting for the non-default language to surface. v9 forced this bug into the light because the operator's task was intrinsically bilingual.

### 4.2 enforce-delegation.sh blocked META's own output types
Early v9 work revealed the hook was blocking META Writes to `reports/`, `projects/*/lessons.md`, and `memory/*.md` — all of which are META's explicitly enumerated output types (#5 Reports, #4 Lessons, memory infra).

**Fix:** Added whitelist for META-owned paths. 20/20 test cases pass.

**Lesson learned:** An enforcement mechanism that blocks your own valid operations is not strict — it's broken. Verify the whitelist against the output type enumeration as part of the invariant spec, not as an afterthought.

### 4.3 Skill bundle mirror drift (DEF-1)
Root framework files were updated v8 → v9 without simultaneously syncing `.claude/skills/eradev/`. Phase 1.E caught it. Wave 5 fixed it (SKILL.md full rewrite + 4 cp-identical mirrors).

**Lesson learned:** Whenever the repo has two copies of the same file (root + skill mirror), **both must be updated in the same commit** or a sync job must be mandatory. Phase 2 backlog item OQ-W5-4: `scripts/build-skill.sh` automation.

### 4.4 Bilingual sync drift (DEF-2)
`meta.md` §14 item 5b DOMAIN was added in Phase 1.C; `meta_RU.md` §14 was left at 12 items. Wave 5 closed it. But `meta_RU.md` §1a still says "5 типов выходов" — the pre-existing gap that Wave 5 explicitly scoped out.

**Lesson learned:** BL-19 says "bilingual sync after any single-language change". The rule exists. It was violated. Classic BL-16 (knowledge without enforcement). The fix is mechanical: a pre-commit hook that flags single-language edits to meta.md / meta_RU.md. Phase 2 backlog.

### 4.5 Template phrasing drift (DEF-3)
`templates/CLAUDE.md.template` Invariant 12 + Language Stack + KILL-TEST still said "include FULL CONTENT" — v8 phrasing that embeds role files into META's own context (the exact anti-pattern v8 self-loading architecture exists to eliminate). Wave 5 rephrased all 3 locations to "self-load".

**Lesson learned:** When you introduce a new architectural pattern (self-loading), **grep the template files for the old pattern's phrasing** — they're copied at project creation and ship stale guidance into every new project until you notice.

## 5. What surprised us

### 5.1 RT-1 consensus missed the drift that Phantom Check caught
5 EN agents + 5 RU agents all approved v9 direction with reasonably high B-scores. None of them flagged the skill mirror drift, the bilingual gap, or the template phrasing. These only surfaced when a dedicated Validator L2 ran the Phantom Coherence Check as a **release gate**, not as a routine review.

This is the Phantom Coherence failure mode in its purest form: 10 agents agreed on the direction and missed the artifacts. S_team was high, B_mean was lower, S_adjusted was the honest number.

**Implication:** Dedicated release gates (not just RT consensus) are load-bearing. The Phantom Coherence Check protocol should become a mandatory step for v9 → v10 and beyond, not an optional polish pass.

### 5.2 The role file vocabulary refactor was larger than expected
When the code-token regex was first run against the v8 role files, each file had 15-40 code-specific tokens (`function`, `API`, `endpoint`, `bug`, `refactor`, `type-check`, ...). After Phase 1.A refactor, each file had <5. The refactor was not cosmetic: v8 role files were *actually* code-biased in their vocabulary to the point where an article-domain agent reading them would naturally default to software metaphors.

**Implication:** The "universal role archetype" layer of the 4-layer architecture was not automatic — it required explicit vocabulary work. The L1/L2 boundary is philosophical but its enforcement is lexical.

### 5.3 Invariant 14 (remote ops + authorization context) was load-bearing for THIS session
The ongoing parallel spawns kept tripping on "prompt injection" safety systems. Adding verbatim operator quotes to agent prompts (the Invariant 14 authorization context pattern) unblocked them. This pattern was added during v8 but v9's scale (20+ parallel spawns) turned it from a nice-to-have into a session-critical mechanism.

## 6. What we are keeping

- **4-layer architecture:** L0 immutable / L1 universal / L2 skin / L3 instance. This is v9's backbone.
- **Modal B-formula:** text/creative/research modalities shift weights, preserve product form.
- **Domain schema:** `domain.type` enum, `B_modality` enum, `ood_scope` enum, backward-compat default (type=code, B_modality=text, ood_scope=text-discrete).
- **Universal role archetypes + vocabulary discipline:** role files stay lexically neutral; code-specific vocabulary lives in L2 skins only.
- **BL split:** 22 universal + 8 code-adapter; future L2 skins inherit from the universal set and override specific items.
- **Phantom Coherence Check as release gate:** mandatory for v9 → v10 and any major cycle.
- **Self-loading context architecture:** agents Read their own role files; META names the path only.
- **Hook whitelist for META output types:** reports/, lessons.md, memory/ all writable by META.

## 10. Final synthesis — what v9 taught us about EraDev itself

EraDev was never code-specific. The v8 framework was universal in structure and code-biased in vocabulary. v9 removed the code bias from the vocabulary; the structure didn't need to change. The hardest part of universalization was not designing the abstraction — it was finding the lexical traces of the narrower domain in files that *looked* neutral.

This validates a claim that has been implicit since v7: **the role archetypes (Visionary, Analyst, Builder, Validator, Coherent) are domain-invariant; the artifacts they work on are domain-variant**. The artifact type (code, article, chapter, config) is an L2 concern; the roles are L1 and should never hard-code artifact assumptions.

The other claim v9 validated: **B = F·E·(1-σ)·Λ is a statement about epistemic coherence, not about software quality**. Whenever you want to know "did this process produce something that matches its intent, without contradiction, informed by prior experience?" — that's the formula. Code was one application. Articles, books, plans, configurations, and research are others.

v9 is the point at which EraDev stops being a software framework that could theoretically be used for writing and becomes a coherence framework that happens to have a well-developed code adapter.
