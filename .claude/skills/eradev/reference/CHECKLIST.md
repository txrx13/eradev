# EraDev -- Universal Verification Checklist
# Не привязан к проекту. Адаптируй в projects/<project>/checklists/.

---

## 1. Pre-Commit

- [ ] Код компилируется без ошибок
- [ ] Нет TODO/FIXME без привязки к задаче
- [ ] Нет закомментированного кода (мертвый код = Muda)
- [ ] Нет хардкод секретов (ключи, токены, пароли)
- [ ] Нет отладочных console.log / fmt.Println / print
- [ ] Все новые функции имеют минимальную документацию
- [ ] Линтер проходит без ошибок
- [ ] Тесты проходят (unit, если есть)
- [ ] Изменения соответствуют scope задачи (нет scope creep)
- [ ] Fix chain counter: если это 3-й fix подряд -- СТОП, вернись к спецификации

---

## 2. Pre-Deploy

- [ ] Все тесты проходят (unit + integration)
- [ ] Build артефакт собран для целевой платформы
- [ ] Артефакт не stale (timestamp сборки = текущая сессия)
- [ ] Конфигурация среды проверена (env vars, ports, paths)
- [ ] Rollback-план задокументирован ДО деплоя
- [ ] Feature flag включен, если применимо
- [ ] Health check endpoint отвечает после деплоя
- [ ] Мониторинг 30 мин после protocol/infra changes
- [ ] При canary deploy: метрики canary vs stable сравнены
- [ ] DNS/TLS: проверить если менялись домены или сертификаты

---

## 3. Security Baseline

- [ ] TLS: MinVersion >= 1.2, запрещены слабые cipher suites
- [ ] Все эндпоинты требуют аутентификации (кроме public)
- [ ] Rate limiting на публичных эндпоинтах
- [ ] Input validation: нет SQL injection, XSS, path traversal
- [ ] Sensitive data не попадает в логи (пароли, токены, PII)
- [ ] Error responses не раскрывают внутреннюю структуру
- [ ] Security headers: HSTS, X-Content-Type-Options, X-Frame-Options
- [ ] Зависимости проверены на известные CVE
- [ ] Права доступа к файлам/директориям минимальны (principle of least privilege)
- [ ] Секреты хранятся в env vars или secret manager, не в коде

---

## 4. RT-3 Acceptance Criteria

> Используется в Round Table 3 (финальная верификация).
> Все пункты должны быть PASS. Любой FAIL = блокировка.

### 4.1 Функциональность
- [ ] Задача выполнена полностью (не частично)
- [ ] Edge cases проверены (пустые данные, граничные значения, конкурентность)
- [ ] Обратная совместимость сохранена (или миграция описана)
- [ ] Нет регрессий в существующем функционале

### 4.2 Когерентность (ODTOE)
- [ ] B(agent) > 0.5 для каждого участника
- [ ] S_team > 0.7 (однородность команды)
- [ ] Нет агента с B = 0 по любой компоненте (F, E, sigma, Lambda)
- [ ] fix rate < 30% за сессию

### 4.3 Процесс
- [ ] Все агенты отработали свою роль (нет пропущенных)
- [ ] Андон не проигнорирован (если был поднят -- задокументирован)
- [ ] Decision Log обновлен
- [ ] Паттерны добавлены в MEMORY.md (если обнаружены новые)
- [ ] spiral_log.md обновлен (новый виток)

### 4.4 Документация
- [ ] Изменения отражены в релевантных docs
- [ ] MEMORY.md актуален (нет устаревших правил)
- [ ] Чеклисты не противоречат друг другу (DRY)

## 5. Severity Levels

| Уровень | Значение | Действие |
|---------|----------|----------|
| BLOCK | Нарушение = остановка коммита/деплоя | Исправить немедленно |
| WARN | Потенциальная проблема | Исправить до следующего RT |
| INFO | Рекомендация | На усмотрение команды |

> Все пункты секций 1-4 по умолчанию имеют severity BLOCK.
> При адаптации для проекта -- можно понизить конкретные пункты до WARN/INFO.
> Понижение фиксируется в Decision Log проекта с обоснованием.
