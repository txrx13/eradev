> Тип: article
> Модальность: research
> Применяется к проектам с `config.md` содержащим `domain.type: article`
> Родительские BL: BOOTSTRAP_LESSONS_universal.md (22 универсальных BL наследуется)

> Вышестоящая математика: eradev.md Section II.1 (веса B_research)
> Живой эталонный проект: projects/odtoe-articles/

## Назначение / Когда META загружает этот скин

META загружает этот скин, когда `config.md` проекта объявляет `domain.type: article` и `domain.skin: templates/domain_skin.article.md`. Скин передаётся каждому ролевому агенту дополнительно к `roles/{role}_EN.md`. Он НЕ заменяет файл роли. Скин нацелен на статьи с теоремами/доказательствами/деривациями (корпусная работа типа ODTOE), НЕ обзорные статьи, НЕ позиционные, НЕ нарративные эссе — см. «Known Out-of-Scope».

## Модальная B-формула (research-веса)

| Компонент | Вес | Обоснование |
|---|---|---|
| F (Фокус) | **0.30** | Обзор литературы + чтение преамбулы/эталона — доминантный гейт. |
| E (Выравнивание) | **0.20** | Выравнивание с интентом важно, но ограничено физической/логической корректностью. |
| (1-σ) (Согласованность) | **0.35** | **Доминантный.** Единственная логическая несогласованность в цепочке доказательства фальсифицирует весь результат. |
| Λ (Опыт) | **0.15** | Наименьший вес. Память помогает, но свежий обзор корпуса может холодно-стартовать новую статью. |

## Переопределения фокуса ролей

### Visionary (фокус на статьях)
- **ПЕРВЫЙ якорь:** Прочитать `thesis` и `abstract`. Прочитать TOC корпуса. True North = *какое научное утверждение добавляет эта статья?*
- **Основной режим отказа:** «Корпусная коллизия» — одобрение тезиса, дублирующего существующую корпусную статью.
- **Jidoka:** Q1 утверждение НОВОЕ? / Q2 тезис фальсифицируем? / Q3 структура секций совпадает с эталоном ODTOE?

### Analyst (фокус на статьях)
- **ПЕРВЫЙ якорь:** Прочитать Check-First (8 пунктов из `odtoe-articles/config.md`). Если не пройден — СТОП. Прочитать 3 ближайших соседа в корпусе (BL-29).
- **Определение артефакта:** Таблица декомпозиции по секциям: секция → утверждения → требования к источникам → требования к деривации.
- **Основной режим отказа:** Пропуск Check-First.
- **Jidoka:** Q1 Check-First пройден? / Q2 для каждого утверждения источник указан? / Q3 ресурсные конфликты (`\Lambda`-коллизия)? / Q4 EN перевод в плане (BL-19)?

### Builder (фокус на статьях)
- **ПЕРВЫЙ якорь:** Прочитать `ODTOE_article.tex` (эталон формата). Прочитать 3 ближайших соседа (BL-29). Прочитать преамбулу из `odtoe-articles/config.md`. НЕ начинать прозу до завершения трёх чтений.
- **Определение артефакта:** Все 8 двуязычных файлов одновременно. `{RU,EN} × {.tex,.pdf,.docx,.md}`. Builder НЕ отмечает Done пока все 8 не существуют (BL-19).
- **Основной режим отказа:** Черновик прозы без контура + таблицы утверждений + таблицы требований к источникам от Analyst.
- **Вторичный:** «Сначала RU, EN потом» — нарушение BL-19.
- **Третичный (article-специфичный):** Пропуск маркеров доказательств. Каждое существенное утверждение ДОЛЖНО иметь `% [FACT: source]`, `% [DERIVATION: axiom]`, `% [HYPOTHESIS: testable via X]`, или `% [OPEN: reason]`.
- **Jidoka:** Q1 `ODTOE_article.tex` и 3 соседа прочитаны (F)? / Q2 черновик совпадает с контуром+таблицей (E)? / Q3 `\Lambda`-коллизии (1-σ)? / Q4 маркеры доказательств (Λ)? / Q5 RU и EN для секции ПЕРЕД переходом (BL-19)?

### Validator (фокус на статьях)
- **ПЕРВЫЙ якорь:** Прочитать план Analyst + набор 8 файлов Builder. Прочитать 7 верификационных проверок из `odtoe-articles/config.md`. Validator владеет финальным гейтом для всех 8 проверок.
- **Основной режим отказа:** Запуск только cite_check и PASS, пока статья имеет фактуальные несогласованности (напр., «аннотация N=120, Таблица 2 N=118»).
- **Вторичный:** Доверие маркерам доказательств Builder без аудита.
- **Jidoka:** Q1 все 8 проверок запущены? / Q2 для каждого [FACT] — цитирование разрешается И источник поддерживает утверждение? / Q3 для каждого [DERIVATION] — цепочка явная и полная? / Q4 числа ВНУТРЕННЕ СОГЛАСОВАНЫ? / Q5 обе версии RU и EN валидированы? / Q6 (Skin-DEF-f): для каждой `\tag{}` формулы — деривация / цитирование / аксиоматическая метка / маркер гипотезы? / Q7 (Skin-DEF-e): self_cite_rate вычислен, вердикт по лестнице?

### Coherencer (фокус на статьях)
- **ПЕРВЫЙ якорь:** Прочитать полный набор 8 файлов. Прочитать глоссарий ODTOE (46 терминов). Прочитать 3 ближайших соседа корпуса. Coherencer заботится о *вписывании этой статьи в корпус*.
- **Определение артефакта:** Корпус + эта статья = новый корпус. L2 Coherencer работа.
- **Основной режим отказа:** «Глоссарный дрифт» — термин, определённый в глоссарии как X, используется в статье со значением Y.
- **Вторичный:** Фантомная когерентность между RU и EN.
- **Jidoka:** Q1 каждый технический термин по глоссарию (BL-29)? / Q2 коллизии символов с корпусом? / Q3 формулы из корпуса совпадают дословно? / Q4 RU и EN структурно эквивалентны? / Q5 независимый спот-чек 3 формул?
- **Двуязычная синхронизация (BL-19):** Coherencer — ПРИНУДИТЕЛЬ правила 8 файлов. Коммит ЗАБЛОКИРОВАН если <8 файлов. Коммит ЗАБЛОКИРОВАН если размеры файлов расходятся >50%.

## Протокол верификации (cite_check расширенный)

### Шесть cite_check проверок

| # | Проверка | Кто | L1/L2 | Механизм |
|---|---|---|---|---|
| **C1** | **Полнота библиографии** — каждый `[N]` в тексте имеет запись; каждая запись цитирована | Validator | **L1** | Структурная grep-проверка |
| **C2** | **Атрибуция цитирования** — утверждение X, цитирующее `[Smith2020]`, действительно поддержано Smith2020 | Validator | **L2** | Чтение источника |
| **C3** | **Синтаксическая валидность DOI / arXiv ID** — каждый DOI/arXiv ID совпадает с regex | Validator | **L1** | Чистый regex |
| **C4** | **Внутренние перекрёстные ссылки** — `§3.2`, `\ref{thm:main}`, `\eqref{eq:main}` разрешаются | Validator | **L1** | Рендеринг/парсер |
| **C5** | **Здравость самоцитирования** — каждое самоцитирование нагрузочно (не padding). Количественная лестница (Skin-DEF-e): 0-30% PASS / 30-50% NOTES / 50-70% NOTES ESCALATED / ≥70% FAIL | Validator + Coherencer | **L2** | Суждение + порог self_cite_rate |
| **C6a** | **Фактуальная согласованность** — числа в аннотации совпадают с телом, таблицами, рисунками | Validator | **L2** | Кросс-ссылочный скан |
| **C6b** | **Провенанс формул (Skin-DEF-f)** — каждая `\tag{}` формула имеет Derived / Cited / Axiomatic / Conjectured маркер | Validator | **L2** | `grep -B3 -A1 '\\tag{'` + ручная классификация |

### Блок верификации

```
method:           cite_check
command:          гибрид — L1 (C1/C3/C4) автоматизируемы, L2 (C2/C5/C6a/C6b) — суждение Validator.
                  Компиляция: `tectonic ODTOE_{topic}.tex && tectonic ODTOE_{topic}_EN.tex`.
success criteria: все 6 cite_check проверок PASS И все 8 config.md проверок PASS
                  И все 8 двуязычных файлов присутствуют (BL-19) И PDF компилируется чисто.
                  C5 вердикт по количественной лестнице (Skin-DEF-e).
failure recovery: C1 → добавить запись ИЛИ цитирование; C2 → перечитать источник;
                  C3 → исправить синтаксис; C4 → исправить ссылку; C5 → обосновать;
                  C6a → выровнять числа; C6b → добавить деривацию / указатель / метку.
independence check: Validator НЕЗАВИСИМО пересчитывает выборку формул.
                  Phantom coherence (BL-5): если оба согласны, но ни один не пересчитал — PHANTOM.
```

### Контракт размера выборки

`sample_size = max(3, ceil(sqrt(total_formulas)))`. Отбор ДЕТЕРМИНИРОВАННЫЙ: (1) формула из аннотации, (2) из основных результатов, (3) из приложения/поздней секции.

## Протокол RT-фаз для статей

### Три точки вызова RT

1. **RT-0 (Visionary соло, РЕКОМЕНДУЕТСЯ):** тезис / корпусная коллизия. APPROVED / REJECTED / OUT-OF-SCOPE.
2. **RT-1 (обязательный, полная пятёрка):** контур + таблица утверждений + план Analyst. Builder НЕ начинает до одобрения.
3. **RT-2 (обязательный, перед подачей):** все 8 верификационных проверок + 6 cite_check + BL-19 проверка 8 файлов.

### Одиночный Builder с по-секционным ритмом

Ритм внутри одного Builder:
1. Черновик секции I в RU `.tex`
2. Сразу черновик секции I в EN `.tex` (BL-19)
3. Компиляция обоих (`tectonic` — ловит LaTeX-ошибки рано)
4. Аннотация маркерами доказательств для всех существенных утверждений
5. Переход к секции I+1

**Исключение (только L/XL):** для XL-статьи (>8000 слов, >4 секции) Analyst МОЖЕТ разделить между двумя Builders по владению секциями. Гейт Coherencer ОБЯЗАТЕЛЕН.

## Примеры (3 конкретных)

### Пример 1: Неподдержанное утверждение (C2 отказ)
- **Сценарий:** Builder пишет секцию III, цитирует `[Smith2020]` для утверждения λ_L > 0 для всех состояний. Smith2020 доказывает λ_L > 0 только для подкласса. Утверждение сильнее источника.
- **Роль-ловец:** **Validator** (C2, L2).
- **Исправление:** Ослабить утверждение ИЛИ найти поддерживающий источник ИЛИ деривация.

### Пример 2: Противоречие контура между секциями (σ-отказ Coherencer)
- **Сценарий:** Секция III: «метрика — функционал информационного состояния наблюдателя». Секция V: «балковая метрика объективна и не зависит от наблюдателя». Взаимное противоречие.
- **Роль-ловец:** **Coherencer** (σ-спайк).
- **Исправление:** Visionary уточняет какое определение нагрузочное; контур переписывается.

### Пример 3: Числовая несогласованность аннотация vs таблица (C6 отказ)
- **Сценарий:** Аннотация: «120 симуляций». Секция IV: «N=120». Рис. 4: «N=120». Таблица 2: «118 наблюдателей». 120 симуляций запущено, 2 исключены по QC, но исключение нигде не упомянуто.
- **Роль-ловец:** **Validator** (C6a, L2).
- **Исправление:** Обновить аннотацию/тело/рисунок: «120 запущено; 118 проанализировано после QC-фильтрации».
